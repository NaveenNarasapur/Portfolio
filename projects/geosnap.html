GeoSnap: privacy-first geotagging camera PWA

2026Solo projectReact 19 · TypeScript · Vite · piexifjs · Workbox · Cloudflare PagesSource on GitHub

Problem

Field and site photos often need trustworthy location data: proof of a visit, an inspection, a delivery. Phone cameras either strip location or bury it, and most "GPS camera" apps upload photos to a server and draw coordinates onto the pixels, which is lossy and can't be read back by software. I wanted a tool that writes real EXIF GPS tags, never uploads the photo, and is honest about whether it worked.

Architecture

  • Capture. On Chromium with a rear camera, ImageCapture.takePhoto() returns a full-sensor JPEG; elsewhere the frame is taken from the video stream at native resolution. Camera tracks are stopped as soon as the user leaves the screen.
  • Lossless metadata rewrite. For GPS-only and "original" exports at quality ≥ 92%, the camera's JPEG bytes are kept and only the APP1/EXIF segment is replaced, so the compressed image data stays byte-identical.
  • Verify, don't assume. After writing, the file is parsed again and the coordinates compared with the fix. If the check fails the UI does not claim the photo is geotagged.
  • Offline & private. A Workbox service worker precaches only the app shell. There is deliberately no runtime caching, so photos, coordinates and geocoding responses are never persisted.

Key decisions

DecisionAlternativeWhy
Client-only processingUpload to a backend for EXIF writingLocation + photo is sensitive data; no server means nothing to secure or leak, and zero hosting cost.
Rewrite APP1 in placeDecode → canvas → re-encodeRe-encoding loses quality and drops the camera's own metadata. In-place rewrite is lossless.
Independent read-back (exifr)Trust the writer libraryCatches writer bugs, e.g. DMS rounding at 59.99999″, that a single library would hide.
Lazy-load the editorOne bundleKeeps first load at ~82 kB gzip; the overlay editor (~18 kB) loads on demand.

Limitations

  • PNG and WebP GPS metadata is not reliably read by common photo viewers, so those exports show coordinates only as an overlay, and the UI says so.
  • Safari and Firefox lack ImageCapture and torch control; those paths fall back to stream-resolution frames.
  • Real-device checks (GPS accuracy outdoors, iOS install flow) are still a manual checklist.

Next version

  • Add automated EXIF round-trip tests and run them in CI on every push.
  • Batch capture with a per-session GPX track export.
  • Optional signed hash of image + coordinates to make tampering detectable.
