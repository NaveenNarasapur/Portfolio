DDoS flow detection: ML pipeline + inference service

2025 → rebuilt 2026Python · scikit-learn · FastAPISource on GitHub

Defensive project: detection only, on a public offline dataset. No traffic generation.

Problem

Classify network flows (CICFlowMeter features) as benign or DDoS so that false alarms stay rare, because every alert costs analyst time. The project began in 2025 as unsupervised BIRCH clustering with a Proof-of-Work mitigation layer; in 2026 I rebuilt it as a reproducible, tested pipeline and kept the original approach as a baseline.

What the numbers do and don't say. This file contains one LOIC attack and is close to linearly separable, so near-perfect supervised scores mostly reflect the dataset. The informative results are the differences:

  • Random Forest was chosen by a rule fixed in advance: lowest false-positive rate with recall ≥ 99%.
  • Removing the Init_Win_bytes_* features, which partly fingerprint the attacker's TCP stack, barely changed Random Forest (6 → 7 false positives) but raised gradient boosting's from 7 to 102. That model was leaning on the fingerprint.
  • BIRCH collapsed into one dominant cluster and flagged nearly everything. A high silhouette score (the 2025 report had 0.981) doesn't mean useful detection.
  • A random split scored higher than the temporal split for every model: the leakage effect of neighbouring flows from the same burst.

Engineering

Modular package (data, features, models, train, evaluate, predict, API), YAML config with CLI overrides, JSON structured logs, 29 tests (95% coverage) on Python 3.11 and 3.13 in CI. The API fails closed when no keys are configured, returns 422 naming any missing feature, and caps batch size.

Limitations

  • One attack, one day: cross-dataset evaluation (CIC-DDoS2019) is the next step.
  • The Mininet integration is documented (a CSV → API bridge) but was not run; it needs Linux with Open vSwitch.
